# Domain docs

This repository uses a single domain context. Before exploring the domain, read the root `GLOSSARY.md` and relevant decisions in `docs/adr/` when those paths exist. Continue if either is absent. Use `/domain-modeling` to record terms and decisions as they are resolved.

Use glossary terms in issue titles, specs, tests, and proposals. If a proposal conflicts with an ADR, cite the ADR and explain the proposed change.
